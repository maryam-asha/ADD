# PM (project management) — phase 1 implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Projects with members and tasks, a Kanban board, a list, "My tasks" and a task panel — a module of its own, outside HR.

**Architecture:** A new Laravel package `packages/add/pm` (namespace `Add\Pm`, tables `pm_*`) mounted by ADD Core like `add/inventory`: the package defines its routes, abilities and a `PeopleDirectory` contract; ADD binds the contract to its staff and registers the abilities as permissions. ADD OS gets a module `src/add-os/modules/pm` with its own sidebar section, open to every staff account and every employee.

**Tech Stack:** PHP 8.3 · Laravel 12 · orchestra/testbench (package tests) · Vue 3 + TypeScript · Naive UI · Tailwind v4 · vue-i18n · `vuedraggable` 4.1 (already a dependency) · Vitest.

**Spec:** `ADDCore/docs/superpowers/specs/2026-11-14-project-management-design.md` (decisions 1–9 are binding).

## Global Constraints

- PM is **not HR**: nothing in `packages/add/pm` imports `Add\Hr\*`, and nothing in `packages/add/hr` imports `Add\Pm\*`.
- People are **user ids**; PM stores no name, phone or email. Names come from `PeopleDirectory` at read time.
- Only `pm.projects.manage` creates, edits, archives a project and sets its members and lead.
- Statuses, fixed, in board order: `todo`, `in_progress`, `review`, `done`.
- Priorities: `urgent`, `high`, `normal`, `low`, or none (null). Colours: urgent → `danger`, high → `warning`, normal → `info`, low → neutral; always with the `carbon:flag` icon and the label.
- Tones (project colour), names only: `olive`, `teal`, `slate`, `green`, `cyan`, `stone` → `var(--add-brand-smart-olive)`, `--add-brand-deep-teal`, `--add-brand-levant-deep-teal`, `--add-brand-soft-growth-green`, `--add-brand-signal-cyan`, `--add-brand-aleppo-stone`. Never orange, never antique copper, never a hex (ADD OS invariant 2).
- One level of subtasks: a subtask's `parent_id` points at a task whose own `parent_id` is null.
- ADD OS: every string in `ar` and `en`; Carbon icons only, then `pnpm icons`; no quoted `"word:word"` literal that is not an icon (use `defineModel`, never an `update:*` emit literal); `<dt>` labels need `font-normal`.
- ADD Core tests: Laragon PHP `C:/laragon/bin/php/php-8.3.33-nts-Win32-vs16-x64/php.exe` with a throwaway `APP_KEY`; package tests via `vendor/bin/phpunit -c packages/add/pm/phpunit.xml`. ADD OS: run only the specs a task touches (`pnpm vitest run --exclude ".claude/**" <paths>`); the full suite only when the product owner asks.
- `composer update add/pm` may reach the network: ask the product owner before running it.
- Nothing is committed unless the product owner asks; both repos carry other sessions' uncommitted work — stage only this plan's files, never a whole directory.

## Review Focus

1. **A member removed from a project while assigned open tasks** — they are unassigned from that project's unfinished tasks (done tasks keep their history); they no longer see the project. Test in Task 4.
2. **An assignee who is not a member** — refused with 422 (`assignee_not_member`), from the board, the panel and the API alike. Test in Task 5.
3. **A due date before the start date** — refused with 422 on create and update. Test in Task 5.
4. **An archived project** — read-only: no new task, no edit, no move (409 `project_archived`); its tasks leave "My tasks" and its counters. Test in Task 5.
5. **A subtask of a subtask** — refused with 422 (`subtask_depth`); subtasks never show as board cards, only as a count on their parent. Test in Task 5.
